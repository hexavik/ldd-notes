
The role of a module is to extend kernel functionality; modularized code runs in kernel space.
A module is linked only to the kernel, and the only functions it can call are the ones exported by the kernel; there are no libraries to link to.

Because no library is linked to modules, source files should never include the usual header files. Only functions that are actually part of the kernel itself may be used in the kernel modules. Anything related to the kernel is declared in headers found in the kernel source tree you have set up and configured.

## Check Loaded Modules

```bash
lsmod
```

`lsmod` is a user-space utility. This internally read `/proc/modules` which is generated by the kernel from its internal linked list of `struct module`.

### Check a module info

```bash
modinfo <module_name>
```

## Kernel Module vs Applications

> [!Quote] Mental Model
> Think of an *application* as a **customer** and a *kernel module* as a **department within the company**. The customer asks for things; the department provides them.

| Feature               | User Space Application                                    | Linux Kernel Module                                  |
| --------------------- | --------------------------------------------------------- | ---------------------------------------------------- |
| **Entry Point**       | Starts at `main()`                                        | Starts at `module_init()`                            |
| **Exit Point**        | Ends at `return` or `exit()`                              | Ends at `module_exit()`                              |
| **Execution Path**    | Sequential (top-to-bottom)                                | Event-driven (waits for calls/interrupts)            |
| **Libraries**         | Linked with standard libraries (e.g., `libc`, `pthreads`) | No standard libraries, linked only to the kernel     |
| **Functions**         | Can use `printf()`, `malloc()`, `scanf()`                 | Must use kernel equivalents: `printk()`, `kmalloc()` |
| **Memory Management** | Uses Virtual Memory (isolated per process)                | Uses Kernel Address Space (shared global memory)     |
| **Privilege**         | **Unprivileged (Ring 3)**<br>Restricted Access            | **Privileged (Ring 0)**<br>Full hardware access      |
| **Fault Handling**    | Segmentation Fault (only the app crashes)                 | **Kernel Panic** (entire system crashes)             |
| **Storage**           | Lives as an executable file (ELF)                         | Lives as a `.ko` (Kernel Object) file                |
| **Concurrency**       | Managed by the OS scheduler                               | Managed by the driver (interrupts, Locks)            |
